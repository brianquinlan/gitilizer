# Next steps from the ranking agents (2026-11-18)

PRD `RANK-23` has ranking give each item one of seven next steps, and `RANK-24`
asks for a measurement before they are shown: how often each ranking agent's
model, and basic ranking, gives an item the next step the product owner would.
This is that measurement, for all five models. The product owner accepted the
results, and next steps are now part of the ranker: the labels below are the
`next_step` of each item in `eval/ground_truth.yaml`, and `npm run evaluate`
reports next steps on every run. The runs here were made before that, with the
adapter in the appendix; the harness gives the same numbers for basic ranking.

## Final measurement: the product owner's labels

The product owner then labelled every item on the labelling page
(`eval/labeler.html`): the 36 in `eval/ground_truth.yaml`, where they changed 4
of the draft labels, and 20 production items in `eval/next_steps.yaml`. Those 20
were picked from 80 public items on their production list, which had every next
step represented: each agent was run on the 80, 46 got the same answer from all
six runs, and the 20 with the most disagreement, or the least sure answer from
basic ranking, were kept (one of a run of near-identical PRs, `dart-lang/http`
#2099 to #2113). So the 20 are the hard cases, not a sample of the list.

"Exact" is how often the next step was the product owner's; "same side" how
often it was at least on the same side of "on me". The 36 are re-scored from the
`…-next-step-v2-…` runs; the 20 are the `…-next-step-prod-…` runs (three trials
each, one for basic ranking).

## How it was measured

Pointwise strategy, `prompts/v4.md`, all 36 items in `eval/ground_truth.yaml`,
with each model at the setting production uses. Nothing in the application
changed. A small adapter, in the appendix, wraps the ranker's clients:

- For Gemini, Claude and OpenAI, the output schema has `next_step` (one of `review`,
  `respond`, `todo`, `backlog`, `waiting`, `elsewhere`, `not_yours`) in place of
  `actionable`, ahead of `next_action`, `priority` and `reasoning`. The Output
  section of the prompt lists the seven with the words from `RANK-23` and the
  order that settles an item that fits more than one.
- For basic ranking, the yes-or-no `actionable` question is replaced with a
  `choice` question, a question type of the Decisions API that takes named
  options and returns one with a probability for each. The options are the
  same seven, with the same words.

The labels are a draft. The eval set has no next steps, so Claude gave each
item one from the product owner's `why` (or `picked_for` where `why` is
empty), using the order in `RANK-23`. They are in the last section, and the
product owner hasn't checked them. The numbers below move if a label changes;
the model's answers are stored, so no run has to be repeated.

## Effect on the order of the list

The runs without next steps are the unchanged harness on the same day:
`20261118-144323-base-gemini-low-t1`, `20261118-144329-base-gemini-low-t2`,
`20261118-144331-base-gemini-low-t3`, `20261118-144332-base-claude` and the
three `…-base-gpt-6.1-sol-low-t…` runs.

Asking for the next step changed Gemini's ranking and nobody else's. All of
Gemini's change is one item, `dart-lang/http#1841`, which moved from rank 34
to rank 19 in every trial. It is one of the two thumbs-down items, which the
eval set keeps from before the Icebox check replaced thumbs-down. With
`next_step` first, Gemini called it Elsewhere, because a PR covers it, and
scored it as an issue with a PR (0.20) and not as a thumbs-down item (0.00).
Without the two thumbs-down items, Gemini's Kendall tau is 0.771 with next
steps and 0.771 without.

A second arrangement was tried on Gemini: `actionable` kept, and `next_step`
asked last, after the reasoning
(the three `…-next-step-last-gemini-low-t…` runs). It left
`dart-lang/http#1841` at rank 34, but its Kendall tau without the thumbs-down
items was lower, 0.740, and its next steps were no better (81% exact). So the
arrangement in `RANK-2`, the next step in place of `actionable`, is the better
of the two.

The prompt is about 420 tokens longer for Gemini, 9% more input for each item.

## Where the models and the draft labels disagree

Fourteen of the 36 items have at least one model that disagrees with the label
(bold in the last section). Three are missed by every model, and
`dart-lang/tools#2710` by every model but `gpt-6.1-sol`:

- `googleapis/google-cloud-dart#359` (label Elsewhere, every model To do). The
  product owner's reason is that a PR already addresses it. No model finds that
  PR, which is the ranking mistake the earlier evaluations show for this item.
- `dart-lang/tools#2710` (label Not yours, four models Elsewhere). A stacked PR
  with a team review request in a repository the developer isn't responsible
  for. Both fit; the label follows the order in `RANK-23`, and only
  `gpt-6.1-sol` does too.
- `dart-lang/http#1972` (label Waiting, every model Elsewhere). The developer
  asked the reporter a question, and a linked PR is open. Both fit here too.
- `dart-lang/sdk#38148` (label Not yours, models Respond or To do). The other
  thumbs-down item: a new report arrived after the thumbs-down, and the product
  owner still ranks it last.

If the product owner relabels the two items where both answers fit as
Elsewhere, the four models that answered Elsewhere to both gain two each (88%,
89%, 80% and 81% exact), and `gpt-6.1-sol` stays at 87%.

One item fits nowhere. `dart-lang/http#579` is a PR parked for the next
breaking release, and the runs gave it five different answers: Backlog,
Waiting, Review, Not yours and Respond.

## Appendix: the adapter

Run from the repository root, one model at a time:

```sh
node --experimental-transform-types .local/next-step-eval.ts --model gemini-3.8-flash --thinking low --label next-step-gemini-low
```

`.local/next-step-labels.json` holds the draft labels, as in the table above,
with the keys the schema uses.

```ts
// Experiment for PRD RANK-24: asks each ranking agent, and basic ranking, for an
// item's next step (RANK-23) and compares it with draft labels for the eval set.
// Not part of the application: it wraps the ranker's clients without changing them.
//
//   node --experimental-transform-types .local/next-step-eval.ts --model gemini-3.8-flash --thinking low --label next-step-gemini-low
import { readFileSync, writeFileSync } from "node:fs";
import { join } from "node:path";
import { parseArgs } from "node:util";
import { z } from "zod";
import { agentForModel, createLLM } from "../app/ranker/src/agents.ts";
import { DecisionLLM } from "../app/ranker/src/decision.ts";
import { loadDotenv } from "../app/ranker/src/env.ts";
import { evaluate } from "../app/ranker/src/evaluate.ts";
import { loadGroundTruth } from "../app/ranker/src/groundTruth.ts";
import { ASSESSMENT, POINTWISE_OUTPUT, ROOT, type LLM, type OutputSchema, type Usage } from "../app/ranker/src/prioritizer.ts";

export const STEPS: Record<string, string> = {
  review: "A PR is waiting for my review or re-review. I am a requested reviewer, or the default reviewer for the repository, or the author has updated the PR since my last review.",
  respond: "Someone is waiting on me. A question or request addressed to me is unanswered, or my own PR has review feedback I haven't addressed.",
  todo: "It is mine to move forward and nobody is waiting on a reply from me. This covers work I am assigned, said I would do, or recently filed in an area I own. It includes checking whether something is fixed, deciding what to do, finishing or closing my draft, and pinging a reviewer who has been silent for about a week.",
  backlog: "It is mine, but nothing is pressing. It is an old or stale item in an area I own, with no recent activity and nobody waiting, that I could triage or close when grooming.",
  waiting: "I am involved and it is someone else's move. I asked a question, requested changes or requested a review, and haven't had an answer yet.",
  elsewhere: "The thing to act on is a different item. This is an issue with an open PR that fixes it, or a PR stacked on lower PRs that need review first. Name that item in the next action.",
  not_yours: "There is nothing for me to do, now or later. It is outside my stated scope, owned or driven by someone else, a team review request in a repository I'm not responsible for, a mention with nothing asked of me, a PR I already approved, or an item I marked not important with nothing new since.",
};
const KEYS = Object.keys(STEPS) as [string, ...string[]];
const ON_ME = new Set(["review", "respond", "todo", "backlog"]);
const TIE_BREAK = "`not_yours`, `elsewhere`, `review`, `respond`, `waiting`, `todo`, `backlog`";

const OUTPUT = `## Output
You will be shown one GitHub issue or PR at a time, as it looked at \`current_time\`.
Activity marked "(ME)" was done by me. Return a JSON object with \`next_step\`,
\`next_action\`, \`priority\` (0.0-1.0) and \`reasoning\`. Priorities from separate
calls are sorted together into one list, so use the whole scale consistently.

\`next_step\` says whose move it is on this item. It is one of:

${KEYS.map((k) => `- \`${k}\`: ${STEPS[k]}`).join("\n")}

If more than one applies, choose the first of: ${TIE_BREAK}.`;

const props = (ASSESSMENT.json as any).properties;
const Assessment = z.object({ next_step: z.enum(KEYS), next_action: z.string(), priority: z.number(), reasoning: z.string() });
const SCHEMA: OutputSchema<z.infer<typeof Assessment>> = {
  name: "ItemAssessment", zod: Assessment,
  json: {
    type: "object",
    properties: {
      next_step: { type: "string", enum: KEYS, description: "Whose move it is on this item: the one next step that applies, as the Output section defines them." },
      next_action: props.next_action, priority: props.priority, reasoning: props.reasoning,
    },
    required: ["next_step", "next_action", "priority", "reasoning"],
  },
};

const OUTPUT_LAST = OUTPUT.replace("with \`next_step\`,\n\`next_action\`, \`priority\` (0.0-1.0) and \`reasoning\`.", "with \`actionable\`,\n\`next_action\`, \`priority\` (0.0-1.0), \`reasoning\` and \`next_step\`.");
if (OUTPUT_LAST === OUTPUT) throw new Error("variant text not applied");
const AssessmentLast = z.object({ actionable: z.boolean(), next_action: z.string(), priority: z.number(), reasoning: z.string(), next_step: z.enum(KEYS) });
const SCHEMA_LAST: OutputSchema<z.infer<typeof AssessmentLast>> = {
  name: "ItemAssessment", zod: AssessmentLast,
  json: { type: "object", properties: { ...props, next_step: (SCHEMA.json as any).properties.next_step }, required: ["actionable", "next_action", "priority", "reasoning", "next_step"] },
};

const NEXT_STEP_QUESTION = `Following the instructions above, whose move is it on this item? If more than one applies, choose the first of: ${TIE_BREAK}.`;

/** Asks for a next step and carries it through the harness at the start of next_action: "[todo] …". */
class NextStepLLM implements LLM {
  private choices = new Map<string, { step: string; p: number }>();
  private inner: LLM;
  constructor(private agent: string, model: string, thinking: string | null, private variant: string) {
    this.inner = agent === "basic"
      ? new DecisionLLM({ model, fetch: this.decisionFetch })
      : createLLM(agent as any, { model, thinkingLevel: thinking });
  }

  // Basic ranking: replace the yes-or-no "actionable" question with a "choice" question for the next step.
  private decisionFetch: typeof fetch = async (url, init) => {
    const body = JSON.parse(String(init!.body));
    const user = body.input[1].text as string;
    delete body.questions.actionable;
    body.questions.next_step = { type: "choice", instructions: NEXT_STEP_QUESTION, criteria: STEPS };
    const res = await fetch(url, { ...init, body: JSON.stringify(body) });
    if (!res.ok) return res;
    const d = await res.json() as any;
    const a = d?.answers?.next_step;
    if (!a?.choice || !(a.choice in STEPS)) return new Response(JSON.stringify({ error: { message: `no next step: ${JSON.stringify(a).slice(0, 200)}` } }), { status: 400 });
    this.choices.set(user, { step: a.choice, p: Number(a.probabilities?.[a.choice] ?? a.confidence ?? 0) });
    d.answers.actionable = { noul: ON_ME.has(a.choice) ? 1 : 0 };
    return new Response(JSON.stringify(d), { status: 200 });
  };

  async generate<T>(system: string, user: string, schema: OutputSchema<T>): Promise<{ result: T; usage: Usage }> {
    if (schema.name !== "ItemAssessment") throw new Error("this experiment scores one item at a time");
    if (!system.includes(POINTWISE_OUTPUT)) throw new Error("the output format isn't where it was expected");
    const sys = system.replace(POINTWISE_OUTPUT, OUTPUT);
    if (this.agent === "basic") {
      const { result, usage } = await this.inner.generate(sys, user, schema);
      const c = this.choices.get(user)!;
      return { result: { ...(result as any), next_action: `[${c.step}] p=${c.p.toFixed(2)}` } as T, usage };
    }
    if (this.variant === "last") {
      const { result: r, usage } = await this.inner.generate(system.replace(POINTWISE_OUTPUT, OUTPUT_LAST), user, SCHEMA_LAST);
      return { result: { actionable: r.actionable, next_action: `[${r.next_step}] ${r.next_action}`, priority: r.priority, reasoning: r.reasoning } as T, usage };
    }
    const { result: r, usage } = await this.inner.generate(sys, user, SCHEMA);
    return { result: { actionable: ON_ME.has(r.next_step), next_action: `[${r.next_step}] ${r.next_action}`, priority: r.priority, reasoning: r.reasoning } as T, usage };
  }
}

loadDotenv();
const { values: a } = parseArgs({ options: { model: { type: "string" }, thinking: { type: "string" }, trials: { type: "string", default: "3" }, label: { type: "string" }, variant: { type: "string", default: "first" }, workers: { type: "string", default: "6" } } });
const model = a.model!;
const agent = agentForModel(model);
const labels: Record<string, string> = JSON.parse(readFileSync(join(ROOT, ".local", "next-step-labels.json"), "utf8"));
const { runDir, agg } = await evaluate({
  doc: loadGroundTruth(join(ROOT, "eval", "ground_truth.yaml")), fixtures: join(ROOT, "eval", "fixtures"), strategy: "pointwise",
  llm: new NextStepLLM(agent, model, a.thinking ?? null, a.variant!), model, thinking: a.thinking ?? null, promptPath: join(ROOT, "prompts", "v4.md"),
  signals: true, trials: Number(a.trials), now: null, label: a.label ?? `next-step-${model}`, workers: Number(a.workers), out: join(ROOT, "eval", "runs"),
});

// How often the next step matches the label, for each trial.
const results = JSON.parse(readFileSync(join(runDir, "results.json"), "utf8"));
const perTrial = results.trials.map((t: any[]) => {
  let ok = 0, side = 0, n = 0, errors = 0;
  for (const s of t) {
    const m = /^\[(\w+)\]/.exec(s.next_action ?? "");
    if (!m) { errors++; continue; }
    n++;
    if (m[1] === labels[s.id]) ok++;
    if (ON_ME.has(m[1]) === ON_ME.has(labels[s.id])) side++;
  }
  return { n, errors, exact: ok / n, on_me: side / n };
});
writeFileSync(join(runDir, "next_step.json"), JSON.stringify({ labels, perTrial }, null, 1));
console.log(JSON.stringify({ runDir, tau: agg.kendall_tau, perTrial }));
```
