## Description
### Context & Problem

While PR #339 adds resilient gRPC bidirectional streaming pull specifically for handwritten `pkgs/google_cloud_pubsub`, all generated server-streaming REST RPCs (such as Vertex AI `streamGenerateContent`, Gemini `streamGenerateContent`, and Firestore `Listen`) rely on `ServiceClient._makeStreamingRequest()` in `generated/google_cloud_rpc/lib/service_client.dart` (lines 177–241).

Currently, `_makeStreamingRequest()` has two runtime issues:

1. **Non-SSE `application/json` Responses Buffer Until EOF (`service_client.dart:210-217`)**:
   - When `enableSse: false` (or when a Google API returns a chunked JSON array `[obj1, obj2, ...]` with `Content-Type: application/json` instead of `text/event-stream`), lines 213–216 execute:
     ```dart
     final responseBody = await response.stream.bytesToString();
     final json = (jsonDecode(responseBody) as List)
         .cast<Map<String, dynamic>>();
     yield* Stream.fromIterable(json);
     ```
   - Awaiting `response.stream.bytesToString()` blocks until the entire HTTP stream reaches EOF before decoding or yielding the first item, defeating incremental streaming for non-SSE streaming endpoints (see also `googleapis/librarian#2490` and `googleapis/librarian#5533`).

2. **Mid-Stream SSE Error Frames Are Silently Decoded as Empty Messages (`service_client.dart:230-240`)**:
   - When `Content-Type: text/event-stream` is active, an HTTP `200 OK` response header is sent before streaming begins. If an error occurs mid-stream (e.g., quota exhaustion, deadline exceeded, or upstream disconnect), Google APIs emit an SSE `data: {"error": {"code": ..., "message": ..., "status": ...}}` JSON frame.
   - Currently, lines 236–238 decode the `data: ` payload and `yield json` directly to the generated method's `.map(ResponseType.fromJson)`. Because `ResponseType` does not have an `error` field, `ResponseType.fromJson` silently ignores the `"error"` key and yields a default/empty `ResponseType` message instead of throwing a `ServiceException`.

### Proposed Solution

1. **Detect and Throw `ServiceException` on Mid-Stream Error Payloads**:
   - In `_makeStreamingRequest()`, inspect each decoded `Map<String, dynamic>` item (both in the SSE `data:` loop and JSON array stream) for a top-level `'error'` object matching `google.rpc.Status` / Google REST error format (matching the check in `ServiceException.fromHttpResponse` in `lib/src/exceptions.dart:105-110`), and throw the corresponding `ServiceException`.
2. **Incremental Framing for `application/json` Streaming Responses**:
   - Replace the full-stream `await response.stream.bytesToString()` buffer in the `case 'application/json':` branch with an incremental JSON array element splitter/decoder so elements in `[obj1, obj2, ...]` are yielded as chunks arrive over `response.stream`.

### Acceptance Criteria

- [ ] Mid-stream SSE `data: {"error": ...}` frames (and chunked JSON array error elements) throw a `ServiceException` on the returned `Stream` rather than yielding an empty/default response message.
- [ ] `application/json` streaming responses (`enableSse: false`) yield array elements incrementally as HTTP chunks arrive instead of buffering until EOF.
