[2026-10-14 03:16Z, 12d ago] Yusufihsangorgel commented:
    For proto3 the conformance suite requires an unknown integer to round-trip as a number ([EnumFieldUnknownValue][1]). By default Java's [JsonFormat][2] and Go's [protojson][3] print integers only for unknown values. Without `enum-encoding=int`, Showcase [GetEnum][4] can return one, and the Dart client throws on it today. Dart already keeps unknown names, so asking for integers can come later.
    
    I'd generate the value numbers, map known integers to constants, keep unknown ones and accept 0 for NullValue. Should `ProtoEnum` get a nullable number, or would a [Rust-style unknown variant][5] fit better?

    I’d propose nullable number and string members, with declared constants carrying both. Unknown integer values in ordinary open enums use JSON numbers and decimal-string query values. This breaks the existing string-only API. Unknown-name decoding remains outside this representation sketch.
    
    ```dart
    final int? number;
    final String? value;
    const State._(this.number, this.value);
    static const ready = State._(1, 'READY'), unknown = State._(123, null);
    Object? toJson() => value ?? number;
    String toQueryValue() => value ?? number!.toString();
    ```
