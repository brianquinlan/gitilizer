## Description
The `NSInputStream` returned by `toNSInputStream` ignores [`scheduleInRunLoop:forMode:`](https://github.com/dart-lang/native/blob/3cbe319e3c1ec0f9253c126ba3e465e55229c3a4/pkgs/objective_c/src/input_stream_adapter.m#L66-L67), never sends stream events to its delegate, and [hasBytesAvailable](https://github.com/dart-lang/native/blob/3cbe319e3c1ec0f9253c126ba3e465e55229c3a4/pkgs/objective_c/src/input_stream_adapter.m#L191-L193) returns YES even when no data is buffered. So a reader that schedules the stream and waits for events never receives any.

`NSURLSession` schedules request body streams, but because `hasBytesAvailable` returns `YES`, it calls [read:maxLength](https://github.com/dart-lang/native/blob/3cbe319e3c1ec0f9253c126ba3e465e55229c3a4/pkgs/objective_c/src/input_stream_adapter.m#L131) on its single, process-wide `com.apple.NSURLConnectionLoader thread`, which [waits](https://github.com/dart-lang/native/blob/3cbe319e3c1ec0f9253c126ba3e465e55229c3a4/pkgs/objective_c/src/input_stream_adapter.m#L163) until the Dart stream provides data. Until then, no other NSURLSession request in the process can make progress. `package:cupertino_http` sends StreamedRequest bodies this way.

To reproduce, add this to pkgs/objective_c/test/ns_input_stream_test.dart:

```dart
test('hasBytesAvailable when scheduled in a run loop', () {
  final controller = StreamController<List<int>>();
  final inputStream = controller.stream.toNSInputStream();
  addTearDown(inputStream.close);
  inputStream.scheduleInRunLoop(
    NSRunLoop.getCurrentRunLoop(),
    forMode: 'kCFRunLoopDefaultMode'.toNSString(),
  );
  inputStream.open();
  expect(inputStream.hasBytesAvailable, isFalse);
});
```
