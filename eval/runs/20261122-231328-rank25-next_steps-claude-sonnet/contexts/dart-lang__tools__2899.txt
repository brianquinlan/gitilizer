## Description
> [!NOTE]
> This PR was generated by an AI coding agent (Jetski) on behalf of @mosuem.

Supply-chain hardening for `package:boring`'s CI. None of it depends on how the prebuilt libraries are distributed. This is the first PR in a stack; #2866 (bundling the libraries in the published package) builds on it.

- **NASM:** replaces `ilammy/setup-nasm`, which downloads NASM from a mutable branch of its repository without checking the download, with a local composite action, `.github/actions/setup-nasm`. It downloads NASM 2.16.01 directly from nasm.us and verifies a pinned SHA-256 (matching Scoop's manifest). It's used in `boring.yaml` and in `boring_binaries.yaml`, which builds the released Windows libraries.
- **macOS Linux cross-toolchain:** replaces the unpinnable `brew install messense/macos-cross-toolchains/...` tap in the `test` job of `boring.yaml` with a direct download of the `v15.2.0` release tarball (arm64/x86_64) and a SHA-256 check, like the Windows cross-toolchain.
- **`precompile` permissions:** `precompile` runs compilers and other build tools, so it no longer gets `id-token: write` / `attestations: write`. A new `attest` job, which only downloads the `binaries-*` artifacts, attests their provenance before `release` uploads them. `gh attestation verify <file> --repo dart-lang/tools` keeps working.

    Avoid redirecting binary files to `stdin` using `<` on Windows, as some environments or tool configurations can default to text mode for `stdin`, potentially leading to CRLF translation or premature EOF (e.g., if the binary contains `0x1A`).
