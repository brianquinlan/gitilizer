## Description
On Android OS, the list of Root Certificates loaded by the DartSDK SecurityContext is loaded from the directory /system/etc/security/cacerts.

The Root Certificate files placed in this path will match the System Certificates in the Trusted credentials on the Android OS. 

However, even if Certificate is set to Disable on the Android OS, the Root Certificate file will not be removed from /system/etc/security/cacerts. So even if a user sets any Root Certificate to be untrusted, the DartSDK will ignore that setting and trust it.

Steps to reproduce:

1. On AndroidOS, disable the System Root Certificate DigiCert High Assurance EV Root CA in Trusted credentials.
2. Using the `http` package of DartSDK, connect to the server where DigiCert High Assurance EV Root CA will be the RootCA. An example of the code is shown below.
```
dart
// RootCA for www.intellilink.co.jp FQDN is DigiCert High Assurance EV Root CA
http.get(Uri.parse('https://www.intellilink.co.jp'));
```
3. For the reasons explained above, DartSDK trusts the Root Certificate with the disabled setting and establishes communication with it. Note that NET::ERR_CERT_AUTHORITY_INVALID is generated when you connect to https://www.intellilink.co.jp with Google Chrome, which confirms that the above disabled setting is working.

    It depends on how and kind of a certificate was added to the system.
