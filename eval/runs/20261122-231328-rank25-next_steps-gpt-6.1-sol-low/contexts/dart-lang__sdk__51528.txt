## Description
The server requires the http headers to be ordered and case-sensitive, but Dart cannot do this.

For example, in the following code, the key of the request headers received by the server is all lowercase, and the order is also disrupted(possibly `{'b ':'b', 'd': 'd', 'c': 'c', 'a': 'a',}`).

```dart
    final client = HttpClient();
    final request = await client.getUrl(Uri.parse(url));
    final headers = {
      'A': 'a',
      'B': 'b',
      'C': 'c',
      'D': 'd',
    };
    headers.forEach((key, value) {
      request.headers.set(key, value);
    });
```

    > The server requires the http headers to be ordered and case-sensitive, but Dart cannot do this.
    
    That's the bug in the server. Refer to HTTP/1.1 specification. RFC 2616 section 4.2 Message Headers says:
    
    > Field names are case-insensitive.
    > [...]
    > The order in which header fields with differing field names are received is not significant.
    
    I don't know if supporting non-compliant servers which don't follow RFC 2616 is a goal or not for our builtin client. 
    
    I defer to @brianquinlan to make the call.
