### `OPENSSL_SMALL`

`package:webcrypto` compiled BoringSSL with `OPENSSL_SMALL`. It mainly shrinks the precomputed P-256 tables, which every application that uses ECDSA or ECDH needs, so tree-shaking can't remove them. I measured webcrypto's full test suite as a tree-shaken AOT build (`dart build cli`) on Linux x64, with BoringSSL built from source each way:

| | without | with `OPENSSL_SMALL` |
|---|---|---|
| tree-shaken `libbssl_dart.so` | 1.12 MB | 0.91 MB (?19%) |
| untree-shaken `libbssl_dart.so` | 2.98 MB | 2.72 MB (?9%) |
| ECDSA P-256 sign ?2000 | 52 ms | 108 ms |
| ECDH P-256 derive ?2000 | 105 ms | 148 ms |
| AES-256-GCM, 200 MiB | 162 ms | 152 ms |

That's about 50 ?s per P-256 signature, which is fine for both apps and servers. This applies to every target, so `fetch` and `checkout` keep building the same library. All 1520 webcrypto tests pass with either build.

### Sanitizers

The build hook ignored `input.config.code.sanitizer`. So `dart test -p vm-asan` loaded uninstrumented BoringSSL, and `package:webcrypto`'s ASan CI job (google/webcrypto.dart#424) no longer checks BoringSSL. Now, like webcrypto's old build hook:

- With a sanitizer, the `checkout` build compiles with Clang and `-fsanitize=address|memory|thread`, via `BSSL_DART_SANITIZER` in `src/CMakeLists.txt`.
- The `fetch` build mode builds from source in that case, because the prebuilt libraries aren't instrumented. This doesn't contradict "`fetch` fails instead of falling back to CMake": that's about missing or failed downloads, while here no prebuilt library can work.
- A new `asan` CI job runs `test/boring_test.dart` with `-p vm-asan`. Locally, it passes, and the built library references 41 `__asan_*` symbols, compared with none without a sanitizer.

### `.inc` build inputs

BoringSSL has 91 `.inc` files, such as `crypto/fipsmodule/*.cc.inc`, which the `checkout` build didn't list as dependencies, so it didn't rebuild when they changed. google/webcrypto.dart#429 fixed the same issue.

### Testing

Locally on Linux x64: `dart test` (34 passed, 5 skipped), the Wycheproof conformance tests, and `dart test -c cli -p vm-asan test/boring_test.dart`.

Changing `src/CMakeLists.txt` makes the pinned prebuilt libraries stale until the `package:boring binaries` workflow pins new ones after this lands. The `analyze` job only warns about this while the version is `-wip`.
